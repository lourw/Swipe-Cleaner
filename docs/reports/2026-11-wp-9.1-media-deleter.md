# WP-9.1 report — Make the delete path a compile-time guarantee (NFR-5, §6.4, §6.7, §8.3, hard rule 1)

Branch `arch-media-deleter`, cut from `main` at `0501bba`, six commits +
this report. `scripts/validate.sh --full` **PASSED** on the final tree
(ktlint → detekt → check-rules → compile → migrations → 490 simulator
tests, 0 failures → Xcode app builds, Debug and Release).

## What was built

**The split.** `delete` moved off `MediaLibrary` onto a new
`commonMain/data/MediaDeleter` interface that holds **only** `delete`
(WP-8.11's FR-38 `setHidden` will get its own writer interface — the KDoc
and §6.4 say so; nothing was built for it). `MediaLibrary` keeps
everything else and its KDoc now points at the write door. Every reader —
all six ViewModels, `DeckMembership`, `SourceCountsUseCase`,
`PruneQueueUseCase` — takes `MediaLibrary` unchanged, and after this
change none of them can express a delete at all: it is not on their type.

**The binding.** `CommitDeletionsUseCase` takes a `MediaDeleter` (param
`deleter`) instead of a `MediaLibrary`. In Koin, `iosModule` now binds one
`PhotoKitMediaLibrary` instance behind two typed views —
`single { PhotoKitMediaLibrary() }`, `single<MediaLibrary> { get<…>() }`,
`single<MediaDeleter> { get<…>() }` — and `commonModule`'s only
`get<MediaDeleter>()` is the `CommitDeletionsUseCase` line. `CommonModule`
edits stayed inside that binding and its comment (WP-9.2 conflict guard).
`FakeMediaLibrary` implements both interfaces like the production class,
so every existing delete-path test runs unchanged through the new seam.

**Behavior: none changed.** `PhotoKitMediaLibrary.delete` — the WP-7.6
resolved-ids path (FR-26) and the WP-8.3 audit-R1 guards (auth check,
failed-fetch → `Failed`, per-id re-probe before the zero short-circuit) —
was not touched beyond the class header and KDoc. Persist-before-advance,
tokens, and layering are untouched; `CommitDeletionsUseCase`'s body is
identical apart from the field name.

**check-rules.** Guard #5 was replaced. The old grep (`.delete(` in
commonMain files that happen to name `MediaLibrary`) is obsolete — the
compiler now enforces it. The new guard fails any production (`src/*Main`)
file whose **code** names `MediaDeleter` outside a four-file allowlist:
`MediaDeleter.kt` (definition), `CommitDeletionsUseCase.kt` (the single
consumer), `IosModule.kt` (the binding), `PhotoKitMediaLibrary.kt` (the
implementation). Comment-only lines are stripped, so docs may explain the
split. Verified live: a planted `presentation/Sneaky.kt` taking a
`MediaDeleter` trips the guard; the clean tree passes. One find+grep, CI-fast.

## Tests

- **Added:** `NFR-5 no view model resolves MediaDeleter only
  CommitDeletionsUseCase does` (`DiSmokeTest`, real graph). A counting
  `MediaDeleter` overrides the PhotoKit binding (later Koin module wins);
  the six ViewModels that never touch the write door
  (Permission, Home, Albums, Months, Settings, Swipe — all with their
  route parameters, resolved inside `runComposeUiTest` so init coroutines
  stay suspended) must pull **zero** resolutions; `QueueViewModel` pulls
  exactly **one**, transitively through its `CommitDeletionsUseCase` —
  the single sanctioned consumer; a second `CommitDeletionsUseCase`
  resolve adds none (singleton). A ViewModel that grew a `MediaDeleter`
  parameter breaks the ceilings even if the check-rules allowlist were
  edited away.
- **Extended:** `koin graph resolves every app binding` now also resolves
  `MediaDeleter` and asserts both typed views (and the concrete
  `PhotoKitMediaLibrary`) are the one instance.
- **Renamed for the new seam** (bodies unchanged): `FR-25 commit calls
  MediaLibrary delete exactly once with every queued id` → `FR-25 commit
  calls MediaDeleter delete exactly once with every queued id` in
  `CommitDeletionsUseCaseTest` and `QueueViewModelTest`. All other
  delete-path tests (WP-7.6 partial-success, WP-8.3 R1, FR-26/27/28) pass
  unchanged.
