## What was built

Every card in the **Likely Duplicates** deck now shows, above the FR-18
metadata row, its place in its set: `2 of 4 in this set`. The numbers come
from the **unfiltered** duplicate candidates, so a set keeps reading its
full size even after the user decides members away — the label counts the
whole set, not the remaining cards. No other deck shows the label, and the
deck's contents and order, and every Home count, are provably unchanged.

## Design: one candidate pass, memberships ride the deck build

§6.5's budget is one `duplicateCandidates()` call per deck build — the
pre-existing FR-6 test pins it (`assertEquals(listOf(ALL),
library.duplicateCandidatesCalls)`). So instead of a second scan for the
labels, `DeckMembership.duplicateDeck` does the single pass and produces
both answers:

- **Deck order** — `DuplicateGrouper.group(candidates.filterNot { decided })`,
  byte-for-byte the old `duplicateDeckIds` behavior (FR-6, FR-9).
- **Memberships** — `DuplicateGrouper.groups(candidates)` over the
  **unfiltered** candidates; each id maps to
  `DuplicateSetMembership(memberIds, position)` where `memberIds` is the
  whole set newest-first and `position` is the 0-based index in it.

Removing decided ids from a run can only split it, never merge it, so every
deck id is always a member of exactly one unfiltered group. `group()` is
now `groups().flatten()` — one implementation, and a test pins that the
flatten equals the old output.

Threading: `BuildDeckUseCase.invoke` returns
`BuiltDeck(ids, duplicateSets)` (empty map for every other source);
`SessionStart` carries `duplicateSets` through both the fresh and the
resume path (the skipped-ids filter removes deck ids, never memberships);
`SwipeViewModel` stores the map at `start()` and attaches
`duplicateSets[item.id]` in `cardAt()`. `CardState.duplicateSet` is the new
nullable field; `SourceCountsUseCase` keeps calling `duplicateDeckIds`,
which now delegates to `duplicateDeck(...).ids` — same single scan for the
Home count.
