## Root cause

The Bursts count and deck ids enumerate **every frame** with
`includeAllBurstAssets = true` (`PhotoKitSourceFetches.kt`, `forEachBurstId`),
but all six single-asset id lookups passed nil options — PhotoKit's default
view, which carries only one representative per burst. The burst ids the deck
was built from therefore resolved to nothing in metadata paging, and
`SwipeViewModel.cardAt()` gave up on the first unresolved id: the Bursts deck
opened "empty". The same gap made `delete` treat a fetch miss as "already
gone" (audit R1) — a still-present frame could have been marked `DELETED`.

## What was built

1. **One shared, burst-inclusive id lookup** (iosMain
   `PhotoKitAssetLookup.kt`): `fetchAssetsByIds(ids, fetch)` wraps
   `PHAsset.fetchAssetsWithLocalIdentifiers` with
   `includeAllBurstAssets = true` and a `runCatching` that turns the binding's
   nil-on-error into null, so callers separate "PhotoKit could not answer"
   from "no such assets"; `assetById(id)` is the single-asset form. All six
   call sites now go through it: `PhotoKitMediaLibrary.items` and
   `.delete`, `PhotoKitMediaLoader` full-screen image and
   `startOrStopCaching`, `VideoItemCache.fetchAsset`, and
   `PhotoKitMediaSharer.shareResources` (WP-8.1's sixth). `PruneQueueUseCase`
   inherits the fix through `items()`. The `fetch` parameter is the
   options-capture seam (WP-7.7 pattern) the deterministic tests pin.

2. **Audit-R1 delete guards** (`PhotoKitMediaLibrary.delete`, FR-25/FR-26):
   refuses with `Failed` unless `authorizationStatusForAccessLevel(ReadWrite)`
   is Authorized or Limited; a failed id fetch is `Failed`, not "gone"; and
   before the zero-fetch short-circuit each id is re-probed individually —
   only every probe answering cleanly licenses `Deleted(all ids)`. Hard rule
   1 untouched: `CommitDeletionsUseCase` is still the only `delete` caller.

3. **Unresolved deck ids are dropped, not fatal** (FR-6, §6.5 step 2):
   `ensureMetadataLoaded()` removes page ids that did not resolve
   (`deck = deck.filterNot { it in unresolved }`) and advances the loaded
   region only over what resolved or dropped. Drops sit at or beyond the
   loaded end, so undo entries behind the head are never disturbed. The
   decide path pages **before** testing exhaustion, so a deck whose tail is
   unresolvable carries on instead of finishing early; a *failing* page fetch
   keeps the ids for the next trigger (the durable decision still advances,
   NFR-7).

4. **Deck loading state** (FR-6, §5.8/§6.6): `SwipeUiState.loading`
   (default true) is cleared when the start path settles — first card
   published, empty deck published, summary, or start failed. `SwipeScreen`
   renders `DeckLoadingPlaceholder` (raised card-shaped panel, tokens only,
   test tag `deck-loading-placeholder`) while `current == null && loading`,
   so a slow first metadata page never flashes the empty state.

5. **FR-9: the Bursts row counts what its deck shows** — verified, no
   behavior change needed: since WP-8.12 every Home count *is* the deck's
   own query (`DeckMembership.ids`), and the real library's burst count and
   burst deck share one enumeration (`forEachBurstId`). The default kept:
   frames, not burst groups. New tests pin the invariant at both levels so
   it cannot drift.

6. **Contract suite burst cases** (WP-7.7 suite): the fake seeds a two-burst,
   five-frame fixture via `MediaItem.burstId`; the real runner **skips the
   seeded burst cases with a printed reason** (PhotoKit has no burst write
   API) while `FR-9 the Bursts count equals the deck the row opens` still
   runs against a granted host's real bursts. The fix's deterministic pins —
   `includeAllBurstAssets` on the id lookup, null-on-failure — live in
   `PhotoKitFetchOptionsTest` and run on any host.

## Notes / deferrals

- The brief's "reproduce on a device with real bursts first" could not be
  done from the simulator harness; the fix follows the documented
  `includeAllBurstAssets` semantics and is pinned at the options seam. The
  documented fallback (`fetchAssetsWithBurstIdentifier` per frame) is noted
  in `PhotoKitAssetLookup.kt` in case the device check finds
  `includeAllBurstAssets` is ignored by `fetchAssetsWithLocalIdentifiers` —
  that behavior is, as the brief says, undocumented.

  (count deck items = burst frames).

  (kotlin.test constructs one instance per `@Test`); unchanged.
