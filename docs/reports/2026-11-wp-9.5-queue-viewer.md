## What was built

The FR-24 full-screen queue viewer is now safe to use:

1. **Tap fall-through fixed.** The viewer's root `Box` was a plain background
   over the `LazyVerticalGrid`, so a tap on the photo hit the grid tile
   underneath and could open a *different* item. The root now carries
   `pointerInput { detectTapGestures(onTap = {}) }`: it consumes every tap
   that is not one of its own buttons (children are handled first), and
   consuming the down event also stops grid scrolling through the viewer.

2. **Modal for VoiceOver too.** While `state.selected != null` the whole
   background column (header, grid, "Delete N items" CTA) rides
   `Modifier.clearAndSetSemantics { }`, so it leaves the semantics tree
   entirely — VoiceOver cannot reach the grid or the destructive button
   behind the viewer, and the test API can't either (which is what makes
   the "unreachable" test assertable). The grid **stays composed**, so its
   scroll position survives open and close.

   *Choice noted (per the WP brief):* "consume input + own traversal group"
   vs "full-screen dialog" — neither a bare traversal group nor
   `androidx.compose.ui.window.Dialog` gives a testable, guaranteed result
   in Compose Multiplatform 1.12 (a `Dialog` keeps background semantics
   findable by the test API, and VoiceOver behavior for CMP dialogs is not
   guaranteed). The implemented pattern — full input consumption on the
   viewer plus `clearAndSetSemantics` on the background while it is up —
   is robust in both respects and verified by tests. The viewer's two
   buttons are then the only accessible content, i.e. it is its own
   traversal group in effect; no explicit `traversalGroup` API is used
   (not reliably available in CMP 1.12).

3. **Videos play in the viewer.** A queued `MediaType.VIDEO` item now mounts
   the deck's `VideoPlayerSlot` (the sanctioned layering exception,
   AGENTS.md rule 5) **muted and playing**, mirroring FR-16, so an item can
   be checked before the batch delete. `QueueScreen` grew a
   `videoSlot: VideoPlayerSlot = DefaultVideoPlayerSlot` parameter (same
   seam as `SwipeScreen`), threaded to `QueueItemViewer` and fakeable in
   `commonTest`. A video skips the full-screen still decode (NFR-3).
   Photos and Live Photos keep the still (FR-17 hold-to-play stays a deck
   gesture). The NFR-8 description rides a wrapper `Box` since the hosted
   player carries no semantics of its own.

4. **Close icon unambiguous.** The viewer's Close was × (`close`) beside the
   Restore ✓ — but × means *Delete* everywhere else. Close is now
   `arrow_back` (the §5.5 mapping gained "Back / close = `arrow_back`").
   The label stays "Close" for VoiceOver.

5. **Plurals.** `deleteItemsLabel(count)` renders "Delete 1 item" /
   "Delete N items" and is shared by the pinned CTA and the confirm dialog
   title ("Delete 1 item?" / "Delete N items?"), so they cannot drift.
   Checked every count string on the Queue screens: "To delete (N)" and
   "Tap an item to restore it." need no plural form; the DeleteSuccess
   screen's "N deleted, M couldn't be found" reads correctly at 1.

## 👤 Human checkpoints (device / VoiceOver)

1. **VoiceOver**: with the viewer open, swipe through — only the item
   description, Close, and Restore should be reachable; the grid tiles and
   "Delete N items" must not be. Close must announce as "Close, button"
   with a back-arrow glyph.
2. **Video in the viewer on device**: queue a video, open it, confirm it
   autoplays muted and loops, and that Close/Restore stay tappable over the
   UIKit player.
3. **Grid scroll position**: scroll a long queue, open an item near the
   bottom, close it — the grid should still be at the same offset.
4. **Tap safety**: tap rapidly around the viewer body (over where tiles
   used to be) — nothing but Close/Restore should respond.
